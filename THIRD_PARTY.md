# Third-party software, data and source provenance

The Bioinformatics workbench bundles independently licensed programs and libraries, and uses others that the browser loads at run time. Each keeps its own licence: the MIT licence of the Biowasm build framework does **not** relicense the programs it compiled, and none of the licences below applies to the workbench's own text and code. Keep each component's notices and licence files when copying or redistributing its files.

## Command-line programs (WebAssembly, run in the browser)

These are the real programs, compiled to WebAssembly. They run on the student's own computer, inside the web page – in the Terminal, in notebook cells (`!`, `%%bash`) and as the tools of the Galaxy tab. Each folder `assets/vendor/biowasm/NAME/VERSION/` holds the program (`.wasm`, its JavaScript loader, sometimes a `.data` file), its licence, a `NOTICE.txt` (origin and local changes) and `SHA256SUMS`. (The folder of the base module has a notice and checksums only: its licence is the Biowasm licence in `assets/vendor/biowasm/LICENSE.txt`. The four files at the top of `assets/vendor/biowasm/` – the runner, its licence and the two descriptions of the local changes – have a `SHA256SUMS` of their own there.)

**Where the builds came from.** All programs except Bowtie 2, BWA, HISAT2, FreeBayes, `diff` and `cmp`, and the grep that carries out `grep -P` are builds of the [Biowasm](https://biowasm.com) project, downloaded from `https://biowasm.com/cdn/v3/NAME/VERSION/` between 30 September and 10 October 2026 (each `NOTICE.txt` has the date). Bowtie 2, `diff` and `cmp` of GNU diffutils, and GNU grep 3.11 with PCRE2 10.42, were compiled with Emscripten for the course – Bowtie 2 from its release source with a patch for the WebAssembly build (its Makefile; the search runs in the calling thread; a read file that cannot be opened is reported), `cmp` from its release source with a one-line patch, `diff`, grep and PCRE2 from theirs unchanged; they are not Biowasm builds. BWA, HISAT2 and FreeBayes were compiled with Emscripten 3.1.64 by the [genomics-wasm](https://github.com/comparativechrono/genomics-wasm) project (commit `0e5df1fb`; its scripts: MIT), from pinned sources with small portability patches, and checked against native builds of the same sources by its comparison suite; for this site they were linked for the program runner (the `.wasm` files are those that were checked) and FreeBayes was compiled again with its source paths shortened. BWA-MEM2, StringTie, kallisto, mosdepth, featureCounts and Salmon come from the same project (commit `e8c3e15`), compiled with its scripts – with the build machine's folders mapped out of the strings in the programs (`-ffile-prefix-map`, and `--remap-path-prefix` for Salmon's Rust) – and checked with its comparison suites against native builds of the same sources; the first four were linked for the program runner (the `.wasm` files are those that were checked), featureCounts and Salmon, which work on several threads, are used as they were built, in a worker of their own (`assets/js/threads-worker.mjs`, adapted from genomics-wasm's runtime, MIT). Cutadapt, LoFreq, SomaticSniper and Strelka2 come from the same project too (commit `bfacba3`): LoFreq, SomaticSniper and Strelka2 compiled with Emscripten 3.1.64 (again with `-ffile-prefix-map`), Cutadapt's and dnaio's Cython extensions with pyodide-build (Emscripten 5.0.3) for the Pyodide 314.0.7 that comes with them – each checked with the project's comparison suites against native builds of the same sources, Strelka2 also against its own Python 2 workflow. They are used as they were built, each command in a worker of its own (`assets/js/threads-worker.mjs`; Cutadapt: `assets/js/python-worker.mjs`, adapted from genomics-wasm's `runtime/cutadapt-execute.mjs` and `runtime/bracken-execute.mjs`, MIT). The somatic workflows of LoFreq and Strelka2 are Python scripts upstream; genomics-wasm's JavaScript translations of them (`lofreq-somatic.mjs`, MIT; `strelka2-somatic.mjs`, GNU GPL 3 or later) are used unchanged, with a small `index.mjs` of the workbench next to them (the paths of the terminal), and `assets/js/somatic.js` puts them into the terminal: `lofreq somatic`, and Strelka's two steps, `configureStrelkaSomaticWorkflow.py` (with the checks and messages of upstream's configure script) and `RUNDIR/runWorkflow.py`. Because it contains Strelka's help texts and messages, `somatic.js` is under the GNU GPL 3 or later. Kraken2 and Bracken come from the same project as well (commit `ebe3454`): Kraken2's programs and Bracken's `kmer2read_distr` compiled with Emscripten 3.1.64 (with `-ffile-prefix-map`), Bracken's two Python programs unchanged, in the same Pyodide 314.0.7 as Cutadapt – one copy, `assets/vendor/genomics-wasm/pyodide/314.0.7/` – each checked with the project's comparison suite against native builds of the same sources. They run as they were built, each command in a worker of its own (`threads-worker.mjs`; `python-worker.mjs` for the Python programs). Kraken2's Perl and shell scripts and Bracken's shell scripts are not run: `assets/js/metagenomics.js` does what they do – their options, checks, messages and usage texts – with genomics-wasm's `kraken2.mjs` (MIT, unchanged) for Kraken2's programs. Because it contains Bracken's usage texts and messages, `metagenomics.js` is under the GNU GPL 3 or later. Prodigal, HMMER and bustools come from the same project too (commit `46c9418`), compiled with Emscripten 3.1.64 (with `-ffile-prefix-map`) and checked with the project's comparison suites against native builds of the same sources. HMMER's programs were compiled a second time for this site, with one more patch to Easel (`genomics-wasm-build/workbench/hmmer-easel-messages.patch`): Easel takes a program whose parent process is process 1 for a daemon and sends its error messages to the system log, and under Emscripten every program's parent is process 1, so their error messages were lost.
