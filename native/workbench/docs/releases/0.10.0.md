# Native Workbench 0.10.0

**Development prerelease — native Windows x86-64.** This version adds native
tool setup with **Full — recommended**, **Starter** and **Custom** choices.
Full retrieves the existing 32 independently versioned packs, so a new user can
install the complete tool selection without importing each archive separately.
Analysis remains local, with bundled private runtimes and no browser, Docker,
WSL or system Python required for normal application use.

workflow pins, reference files and results. Retain other installed versions
until an applicable upgrade path is chosen; extracting a Starter into another
folder does not automatically migrate data.

## Installing the tools you need

At first launch, choose a setup profile. Existing installations can open
**Tool setup** through the menu or **Manage tools**.

| Profile | Selection |
| --- | --- |
| **Full — recommended** | All 32 reviewed current packs. Already installed exact versions are retained. |
| **Starter** | The three bundled packs: minimap2, SAMtools and BCFtools. No pack download is needed. |
| **Custom** | Starter plus the additional packs you select. |

For Full or Custom, choose **Refresh catalogue**, review the selection and
download size, then choose **Install selection**. Opening Workbench or the setup
window does not start downloads. The official catalogue is signed with the
reviewed publisher key; each archive and its complete file inventory must pass
integrity and compatibility checks before it becomes installed.

A fresh Full installation downloads **3,795,572,848 additional bytes** across
29 packs, beyond the Starter ZIP. The earlier complete-pack assessment measured
about **4.67 GB** of initially extracted files. Allow additional space for
downloads, temporary extraction, private-runtime expansion, references and
results; those are not included in the initial-file estimate.

Progress shows the current download and the complete selection. Cancellation
retains completed packs and removes the incomplete transfer. **Retry** restores
the exact selection after a failure or restart and downloads the unfinished
packs; it does not resume a partial archive from its last byte. Abrupt process
termination may leave temporary staging files, which are never treated as
installed tools.

**Manage tools**, approved additional catalogue sources and offline **Import pack
ZIP** remain available for future official packs and packs from other
developers. Installed tools work offline, and saved workflows retain their exact
pack versions. References and scientific databases remain separately selected
resources; tool installation does not download analysis datasets.

The native Tools/Workflow interface, reusable inputs, Ensembl archive finder,
local reference library, CWL result export, routed DAGs and application icon are
retained. This release does not replace any published pack bytes.

## Validation and scope

The new candidate was built once from
[`5a390acd8440856e3f4e32de237322a18bb82d7e`](https://github.com/comparativechrono/workbench/commit/5a390acd8440856e3f4e32de237322a18bb82d7e)
in [run 37618824677](https://github.com/comparativechrono/workbench/actions/runs/37618824677).
These exact archives are validated for promotion without rebuilding.
This is a new production-trust package; the earlier empty-trust candidate is
retained only as historical development evidence.

The build source gate passed **152 tests with one Windows-only skip**. The
separate Windows pack-manager suite passed **42 tests with no skips**, including
that filesystem case, using the candidate's private interpreter. The new
candidate has passed the following checks in **both ordinary and
space-containing paths on native Windows**:

| Suite | Passed per path | Scope |
| --- | ---: | --- |
| Tool setup | 13 | Native profiles, totals, minimum-size layout, offline Starter, reopening and persisted selection; isolated signed fixtures cover download, cancellation, restart/retry, corrupt archives and signatures. |
| Workspace | 32 | Native tool and workflow interactions, reusable inputs, compatible connections and local scientific execution. |
| References | 8 | Live pinned yeast downloads for all five products, compressed/expanded integrity, cancellation, native compatible selection, offline reuse and provenance. |
| Results, CWL, DAGs and icon | 9 | Scientific output, frozen CWL provenance and independent embedded-runner replay, native connections, diagrams and Windows icon resources. |
| Upgrade from 0.9.0 | 13 | Exact target core inventory, unchanged existing user files/packs, repeat update and post-update offline reference/scientific/CWL execution. |
| Live production Full | 4 | Official signed catalogue, all 32 exact pack versions installed, offline 202-record alignment/BAM truth, usable BED workflow input and offline tool discovery. |

The References helper's optional older updater check was not requested and is
reported as a skip; the separate 0.9.0 updater gate supplies this release's
migration evidence. The updater gate exercises the native updater CLI and its
private runtime, not the folder-picker interaction. Native CWL runner replay
does not claim execution through a Windows CWL engine.

Live Full used the packaged production trust without substitution in both
paths. A separate all-pack fixture gate also passed four checks; its public
test key remains isolated from production trust. Full installation establishes
all-pack installation/coexistence and starter
scientific truth; it does not rerun every optional pack's scientific fixtures.
Offline checks deny Python host socket operations, rather than installing an
operating-system firewall for every native subprocess. Hosted checks do not
establish every physical trackpad, high-DPI/multi-monitor or institutional proxy
configuration. The owner authorized release; no new manual tester acceptance
of these rebuilt bytes is claimed.

The [handover](https://github.com/comparativechrono/workbench/blob/main/knowledge/tool-setup-0.10.0-handover.md)
retains exact identities, initial failed validators and the final production
evidence. Published source/build companions retain their creation-time status;
later release evidence records completion without replacing their bytes.
