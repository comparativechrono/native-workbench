# Native Workbench 0.9.0

**Development prerelease — native Windows x86-64.** This update adds an
exportable CWL workflow to analysis results, clearer dependency diagrams and a
new application icon. The project owner has reported tester acceptance and
authorized release of the exact validated candidate. Analysis remains local,
using bundled private runtimes; no browser, Docker, WSL or system Python is
required for normal Workbench operation.

- [Windows starter](https://github.com/comparativechrono/workbench/releases/download/app-v0.9.0/native-workbench-0.9.0-starter-windows.zip): extract into a separate folder and run `NativeWorkbench.exe`.
- [Updater from 0.8.0](https://github.com/comparativechrono/workbench/releases/download/app-v0.9.0/native-workbench-0.9.0-update-from-0.8.0.zip).

Use the updater matching the installed application version. Close Workbench,
extract the updater outside the existing installation, then run
`UpdateWorkbench.exe`. There is no updater for 0.7.0; a separately extracted
starter does not automatically migrate an existing installation's data.

The starter still includes minimap2 (`align`), SAMtools (`bam`) and BCFtools
(`variants`). All **32 independently versioned tool packs** remain unchanged.
Additional packs can be imported through **Manage tools → Import pack ZIP**,
including offline. Pack versions and saved workflow pins remain independent of
the application version.

## Changes

- **CWL in results:** every newly prepared analysis writes `workflow.cwl` beside
  its plan, methods, diagram and run records. The packed CWL v1.2 document keeps
  the actual dependencies, named inputs and outputs, parameters, exact pack
  versions, file hashes, reference provenance and original execution outcome.
- **Clearer DAGs:** saved SVG diagrams and the native workflow canvas route
  connections around tool cards, with clearer arrowheads. Connections can still
  cross each other, and overlapping cards may need moving to expose their ports.
- **Native icon:** an original SVG of connected nodes forming a “W” produces the
  application's small and large Windows icons.

The native Tools/Workflow layout, reusable inputs, References finder, offline
reference library, saved settings and pinned pipelines remain available.

## Running exported CWL elsewhere

The exported workflow contains an independent Python command runner and does
not import Workbench. To execute it separately, provide a compatible CWL v1.2
engine, Python 3.10 or newer, matching tool-pack files and the required data.
These are external execution requirements, not new Workbench dependencies.
Windows tool binaries are not converted into Linux or macOS binaries, and large
reference databases are not embedded or downloaded by the export.

Input files and compatible executable replacements can be explicitly rebound.
Original hashes remain provenance for the original run; they do not establish
that replacement data or software is scientifically equivalent. External CWL
execution does not reproduce every Workbench biological preflight check or its
Windows process and cancellation handling. See the
[CWL guide](https://github.com/comparativechrono/workbench/blob/main/knowledge/cwl-results.md)
for the contract and examples.

## Validation and scope

The accepted application archives were built from
[`beea34ab29f3e7cb9a7e79dbcfa11c89f40ee59d`](https://github.com/comparativechrono/workbench/commit/beea34ab29f3e7cb9a7e79dbcfa11c89f40ee59d)
and are promoted without rebuilding. The source gate passed **125 checks**,
including validation and controlled-fixture execution through stock `cwltool`.
The original Windows run passed **32 workspace and 9 References/update checks
per ordinary and space-containing path**. These include real reference
downloads and cancellation, integrity/provenance, offline reuse and preservation
when upgrading from 0.6.0. Its long-path gate passed all three checks, completing
the five-stage starter pipeline and verifying 20 output hashes.

After correcting three hosted-desktop validator fixtures, the
[final focused Windows run](https://github.com/comparativechrono/workbench/actions/runs/37489208656)
passed **9 feature checks per path, with no failures or skips**, against the
unchanged application bytes. This covers scientific output, exported CWL and
standalone-runner replay, routed native/SVG diagrams and displayed icon frames.
Four normal and zoomed canvas captures were reviewed. The zoom capture used the
native button command because the VM taskbar covered its physical location;
physical zoom clicks were covered by the separate workspace gate. Earlier
failed validator attempts remain recorded as failures.

The additional **0.8.0-to-0.9.0 updater** passed
[its native gate](https://github.com/comparativechrono/workbench/actions/runs/37527359533)
with **13 checks per path, zero failures and zero skips**. It preserved 202
existing files, including packs, settings, pinned workflows, reference files and
results, verified 70 core files and repeated idempotently. Post-update reference
and scientific/CWL analyses passed. This used the native updater CLI and a
synthetic local reference with host Python socket operations denied; it did not
repeat live reference downloads or test the updater's folder picker.
The [release handover](https://github.com/comparativechrono/workbench/blob/main/knowledge/cwl-dag-icon-0.9.0-handover.md)
retains exact identities, both earlier failed updater-fixture attempts and later
public-download evidence. No new physical-display survey or rerun of every optional
pack is claimed. Native embedded-runner replay is separate from invoking a
Windows CWL engine. Published source/build companions retain their creation-time
status; later evidence records acceptance and release checks without replacing
those accepted archives.
