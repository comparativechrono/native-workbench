BUILD
Linux x86-64; Python 3.12+, GCC, GNU make/binutils, zlib development headers.
Use the pinned Cosmopolitan 3.3.10 compiler archive described in provenance.json.
From the project root:
  python3 tools/build_bwa.py --cosmocc-root /path/to/cosmocc-3.3.10
The script builds both reference Linux and portable APE executables. Its only
changes are compiler/archiver settings, explicit POSIX header declarations and
link settings. Cosmopolitan supplies namespaced zlib. The .exe output selects APE.
Baseline -march=x86-64 uses SSE2; no AVX/AVX2 or host-specific -march=native is
requested. Cosmopolitan may dispatch optimized library operations at runtime.

WORKFLOW CONTRACT
Build an index inside the private run folder, never beside the selected input:
  bwa index -p /run/reference /run/reference.fa
This produces five required files at the chosen prefix:
  reference.amb, reference.ann, reference.bwt, reference.pac, reference.sa
Declare all five outputs. No FASTA .fai is produced by bwa index; samtools faidx
is a separate step if the downstream variant workflow requires that index.
Use the same prefix with bwa mem. The default index algorithm is automatic;
the actual pinned source selects bwtsw above 50 million packed bases and is for
smaller references. Do not force bwtsw for the tiny teaching fixture.
An optional externally supplied .alt file affects ALT-contig interpretation;
it is not generated by index, and is not supplied/tested by this pack.

Paired alignment argument vector, without shell interpretation:
  mem -t 2 -K 1000000 -R @RG\tID:sample\tSM:sample\tLB:library1\tPL:ILLUMINA PREFIX R1 R2
The complete -R value is ONE argument. Its separators must be the two literal
characters backslash and t; BWA rejects actual tab characters in this argument.
Do not allow backslash/control characters in dynamically inserted read-group
identifiers: upstream interprets backslash escapes in that string. ID identifies
the read group; SM identifies the biological sample; LB is the library, not a
lane identifier; PL is the platform. These values must reflect sample metadata.
Paired FASTQ files must have the same read count and corresponding mate names in
the same order; run paircheck first. Plain and gzip FASTQ are supported.
-K fixes the input chunk size for reproducibility across thread counts; changing
chunking can change pairing inference. Tests use 1,000,000 input bases per chunk.
The unmodified command also supports single-end input when R2 is omitted.
Outputs are ordinary unsorted SAM with original BWA supplementary alignment
semantics. This build does not implicitly add -M or alter split-hit flags.

LOCAL DATA AND LIMITS
The application supplies validated absolute local filenames. BWA's unchanged
CLI also contains upstream HTTP/FTP/pipe input facilities; they are not exposed
by these workflows. No network operation is needed for local index/alignment.
The upstream _KO_NO_NET macro is incomplete in this release (unresolved helper
symbols), so it is not enabled and no claim is made that networking was removed
from the binary. No arbitrary BWA CLI command is accepted by the GUI workflow.
BWA is designed for large reference genomes, but this portable build has only
been exercised on the 6,000-base fixture and the supplied yeast reference.
Human-genome-scale RAM, disk, indexing and full-run behavior remain untested.
Indexing can require several GB for large references; repetitive reads can
increase mapping memory. Do not interpret the small executable size as small
data memory requirements. Windows native execution remains pending.

VALIDATION
  python3 validation/validate_bwa.py --output NEW_DIRECTORY
  python3 validation/validate_bwa.py --output NEW_DIRECTORY --practical-dir /path/to/VariantCalling
The validator generates the tiny truth fixture and compares independent Linux
and APE runs. Paths contain spaces and non-ASCII characters. Tests cover plain
and gzip FASTQ, one/two mapping threads, escaped read groups and rejection of
actual-tab read groups, all five byte-identical indexes and exact SAM bytes
after removing only @PG header lines. Alignment records and all other headers
are retained in the comparison. Each backend's tiny variant pipeline recovers
all four exact alleles/genotypes, marks the 12 planted duplicate pairs and
queries both BAM and VCF through their CSI indexes. The optional real-data test
aligns all of yeast lane 1, including gzip input, with the same strict SAM
comparison. It tests BWA against BWA, not agreement between different aligners.
Inputs and reference copies must remain unchanged. This is correctness evidence
on a Linux host, not a timing benchmark or native Windows validation.
